このファイルを `shop/CLAUDE.md` として置き、`shop/` の作業のたびに読むこと。リポジトリ直下の `CLAUDE.md`（レッスン予約の指示書）の「守ること」も引き続き守る。

## 0. 何を作るか

公開中のレッスン予約（`/yoyaku-demo/`）とは別に、`shop/` フォルダに **但馬の小さなお店が「自分の店用」に設定して使える予約ページの見本** を作る。公開URLは `https://takesgi.github.io/yoyaku-demo/shop/` になる。

目的は3つ。
1. 飲食店・サロンの方に「あなたのお店ならこうなります」と見せるデモ
2. 協力先と作る「軽量版の機能リスト」（11/11）の実物と、その下書き（`shop/機能リスト案.md`）
3. AI講座⑥アプリ開発の教材（開発ログを残す）

**軽量版の考え方**：機能を足すより、減らす。お店が迷わず設定でき、止まっても困らず、お客さんの情報をできるだけ持たない。

---

## 1. 守ること

1. **他社の要件定義書・デモ（文章・データ・デザインの数値・名前）を持ち込まない。** この指示書と、自分たちのレッスン予約のコードだけを元にする
2. 作るのはこの指示書に書いたものだけ。迷ったら作らず、開発ログに質問を書いて止まる
3. 素のHTML・CSS・JavaScript、ビルドなし、外部ライブラリなし、外部への通信なし。保存はブラウザの中（localStorage）だけ
4. **レッスン予約（リポジトリ直下）を壊さない。** 共通にできる部品（空きの計算・金額の表示・日付の書き方）は `shop/js/` に写して育ててよいが、直下の `js/` は書き換えない。直下のテスト28件は毎段階で通ること
5. 全画面に「これは見本です。実際の予約は入りません」
6. 見本のお店は架空。店名に必ず「（見本）」を付ける。電話は 0796-00-0000（見本）の形。実在のお店の名前・写真を使わない
7. 金額は「1,200円（税込1,320円）」の形。安さをうたう言葉を書かない
8. 段階ごとに、撮影（390px・768px・1440px）→ console エラー0 → テスト → コミット → 開発ログ → **止まって報告**。push 先は作業用の枝。main への取り込みはたけさんが行う
9. iPhone（Safari）でしか起きない崩れがあることを前回学んだ。入力欄（とくに date・time・select）には前回と同じ指定を最初から入れる

## 2. 業種の型（2つ）

お店は最初に「型」を選び、あとは型ごとの項目を埋めるだけにする。

| | 飲食店の型 | サロンの型（美容室・整体・エステなど） |
|---|---|---|
| 予約の単位 | **席**（テーブル・個室・カウンター）× **人数** | **担当者** × **メニュー** |
| お客さんが選ぶもの | コースまたは「席のみ」→ 人数 → 日付 → 時間 | メニュー → 担当（指名なしも可）→ 日付 → 時間 |
| 重なりの考え方 | 同じ席に同じ時間帯は1組。人数が席の定員を超える席は選ばない | 同じ担当に同じ時間帯は1件。「指名なし」は空いている担当を自動で割り当てる |
| 所要時間 | コースごと（席のみは店が決めた標準時間） | メニューごと |
| 片付け・準備の時間 | 予約の後に◯分あける（店が設定） | 予約の後に◯分あける（店が設定） |

## 3. 見本のお店（最初から2店入れておく。切り替えボタンで選べる）

- **飲食店：「和食 ゆずり葉（見本）」**　昼 11:30〜14:00／夜 17:30〜21:00、水曜定休。席＝テーブル4名×3、個室6名×1、カウンター1名×4。コース＝昼のおまかせ（60分・1,800円）・夜のおまかせ（120分・5,000円）・席のみ（90分・金額なし）。片付け15分
- **サロン：「ヘアサロン こもれび（見本）」**　10:00〜19:00、火曜定休。担当＝3名（うち1名は木曜休み）。メニュー＝カット（60分・4,000円）・カラー（90分・6,500円）・カット＋カラー（150分・9,800円）。片付け10分

金額はすべて税別で持ち、表示は税込併記。見本の予約を各店6〜8件、受けない時間を各店1件。名前は「山田 花子（見本）」の形。

## 4. お店の設定画面（お店側）

レッスン予約の「教室側」にあたる画面に、**設定** を足す。項目は少なく、1画面で終わる量にする。

| まとまり | 項目 |
|---|---|
| お店の基本 | 店名・一言紹介・住所・電話（見本）・地図のURL（任意）・色（5色から選ぶ） |
| 営業 | 曜日ごとの営業時間（**1日2部まで**：昼・夜など）・定休日・臨時休業（日付で） |
| メニュー | 名前・所要時間・金額（税別）・説明（1行）。並べ替えと削除 |
| 席／担当 | 飲食＝席の名前と定員／サロン＝担当の名前と休みの曜日 |
| 予約のきまり | 締め切り（◯時間前まで）・何日先まで受けるか・開始時刻の刻み（15／30／60分）・片付けの時間 |
| お客さんに聞くこと | **「名前だけ」「名前＋電話」「名前＋電話＋メール」の3択**（できるだけ持たない設計。既定は「名前＋電話」） |
| 変更・キャンセル | 連絡方法の文・受け付ける期限の文。**キャンセル料を取る場合**は「キャンセル料あり」をオンにし、金額や率を書く欄を出す。オンのときは、お客さん側の確認画面で予約確定の前に必ず表示する |

- **設定の書き出し・読み込み**：設定をファイル（JSON）に書き出し、別のブラウザで読み込める。お店ごとの設定を受け渡すため
- 予約一覧・受けない時間・見本をリセットは、レッスン予約と同じ動きでよい（型に合わせて「席」「担当」の列を足す）

## 5. お客さん側

- レッスン予約と同じ「4つの不安に聞かれる前に答える」作り（空き具合のカレンダー、金額と時間を出し続ける帯、確定直前の再確認、完了画面の予約番号とこのあとの流れ）
- 飲食店：人数を選ぶと、その人数が入れる席のある時間だけを出す。席の種類（テーブル／個室／カウンター）の希望は「どれでもよい」を既定にする
- サロン：担当の写真は使わない（名前だけ）。「指名なし」を先頭に置く
- 予約番号は `店の頭文字2字-年月日-3桁`
- 完了画面：お店の電話・地図・変更キャンセルの文。確認メールは文面のプレビューだけ（送らない）

## 6. 作る順番（段階ごとに止まって報告）

| 段階 | やること | 終わりの条件 |
|---|---|---|
| 1 | `shop/` の骨組み、設定データの形、2店の見本データ、空きの計算を「席×人数」「担当×メニュー」に広げる、テストページ | テストが全部通る（下の項目を含む）。直下のテスト28件も通る |
| 2 | お客さん側（2つの型） | 2店とも、スマホ幅で予約が完了まで通る |
| 3 | お店の設定画面、書き出し・読み込み、予約一覧・受けない時間・リセット | 設定でメニューや営業時間を変えると、お客さん側の選べる枠がすぐ変わる。書き出したファイルを読み込むと同じ設定になる |
| 4 | 見た目の仕上げ、`shop/機能リスト案.md`、レッスン予約のトップから `shop/` への小さな案内リンク | 撮影と確認がすべて済み、たけさんに main への取り込みを頼める状態 |

### テストに入れること（段階1）

- 4名は2名用の席に入らない／6名は個室だけになる
- 同じ席・同じ担当に、片付けの時間を含めて重ならない
- 「指名なし」で、空いている担当に割り当てられる。全員ふさがっていれば×
- 昼の部に夜のコースが出ない（コースに「昼のみ」「夜のみ」を持たせる）
- 定休日・臨時休業・担当の休みの曜日が×になる
- 締め切り（◯時間前）を過ぎた枠が選べない
- キャンセル料ありのとき、確認画面の文にその金額が入る
- 金額の表示が税込併記になる

## 7. `shop/機能リスト案.md`（段階4で書く）

協力先と11/11に作る機能リストのたたき台。**金額や他社の名前は書かない。** 表は次の4列。

| 機能 | この見本でやっていること | 軽量版（本番）に入れるか | 本番で必要になること |
|---|---|---|---|

行の例：予約の受付／空きの表示／二重予約を防ぐ／仮押さえ／お客さんに聞く項目／確認の連絡（メール・LINE・SMS）／前日のお知らせ／キャンセル料と表示／決済／お店のログイン／設定の変更／複数店舗／止まったときの連絡。
「本番で必要になること」の例：二重予約をサーバー側（データベース）で防ぐ、ログイン、通知の送り先、個人情報の保存場所と消し方、障害のときの連絡の流れ。
最後に「たけさんと協力先で決めること」を箇条書きで残す。

## 8. 作らないもの

決済・会員登録・本物の通知の送信・英語表示・写真のアップロード・複数店舗の一括管理・口コミ・外部サービスとの連携・データベース。
