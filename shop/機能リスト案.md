# 軽量版 予約ページ 機能リスト案（たたき台）

作成 2026-10-29（11/11 の打ち合わせ用のたたき台）
元にしたもの：お店向け予約ページの見本（`shop/`、公開URL `https://takesgi.github.io/yoyaku-demo/shop/`）

**軽量版の考え方**：機能を足すより、減らす。お店が迷わず設定でき、止まっても困らず、お客さんの情報をできるだけ持たない。

「軽量版（本番）に入れるか」の印：**◎ 入れる**／**○ 入れたい（中身を決める）**／**△ 検討**／**× 入れない**
（印は、見本を作った側からの案です。打ち合わせで決めます）

---

## 機能の一覧

| 機能 | この見本でやっていること | 軽量版（本番）に入れるか | 本番で必要になること |
|---|---|---|---|
| 予約の受付 | 飲食店は「コース → 人数と席 → 日付 → 時間」、サロンは「メニュー → 担当 → 日付 → 時間」で受け付ける。確認画面で確定し、完了画面に予約番号（店の頭文字2字-年月日-3桁）を出す | ◎ | 予約をサーバー（データベース）に保存する。お客さんの画面とお店の画面で同じ予約が見えるようにする |
| 空きの表示 | 月のカレンダーに ○（空きあり）△（残りわずか）×（満席・お休み）。いちばん早く取れる日時を上に出す。営業時間・定休日・臨時休業・締め切り・何日先まで・受けない時間・片付けの時間から計算する | ◎ | 空きの計算をサーバー側でも同じきまりで行う（画面だけで計算すると、古い情報で表示されることがある） |
| 席・担当の割り当て | 飲食店は人数が入る席を小さい席から順に、サロンの「指名なし」は担当の並び順に、空いている人を自動で割り当てる | ◎ | 割り当ての決め方を選べるようにするか（下の「本番で検討すること」） |
| 二重予約を防ぐ | 確定ボタンを押した直前に、もう一度空きを確かめる。埋まっていたら「先に予約が入りました。別の時間をお選びください」と案内し、入力は残す。ただし確かめるのはこのブラウザの中だけ | ◎ | **サーバー側（データベース）で防ぐ。** 2人が同時に確定しても、片方だけが入るしくみ |
| 仮押さえ | していない（確定ボタンを押すまで枠は押さえない） | △ | 入れるなら、何分押さえるか・押さえたまま離れた人の枠をいつ戻すか |
| お客さんに聞く項目 | 「名前だけ」「名前＋電話」「名前＋電話＋メール」の3択（既定は名前＋電話）。ご要望の欄は持たない | ◎ | 聞いた情報の保存場所、だれが見られるか、いつ消すか（個人情報の扱い） |
| 確認の連絡（メール・LINE・SMS） | 送らない。完了画面に予約番号と、メールの文面の見本を出すだけ（メールを聞かない設定のお店は「確認メールはありません」と出す） | ○ | 送る手段（メール・LINE・SMS のどれか）、送り先、送れなかったときの扱い、送るための費用 |
| 前日のお知らせ | していない | △ | 送る時刻、送る手段、止め方（お客さんが「いらない」と言えるように） |
| キャンセル料と表示 | お店が「キャンセル料あり」にすると、金額や率の文を、確認画面の確定ボタンの前に必ず表示する。完了画面と確認メールの文面にも入れる | ◎（表示だけ） | 表示の文をお店が決める。キャンセル料を実際に受け取るしくみは決済と同じく持たない |
| 決済 | 扱わない（「お支払いはお店でお願いします」と表示） | × | 入れない。入れるなら別の計画にする |
| お店のログイン | していない（見本のため、画面上部の「お店側」ボタンでだれでも見られる） | ◎ | ログイン、パスワードを忘れたとき、お店の人が何人で使うか |
| 設定の変更 | お店側の「設定」1画面で、お店の基本・営業（1日2部まで・定休日・臨時休業）・メニュー・席／担当・予約のきまり・聞く項目・キャンセルの文を変えられる。保存の前にまちがいを調べ、保存するとすぐお客さん側に反映する。設定をファイルに書き出し・読み込みできる | ◎ | 設定をサーバーに置く。だれがいつ変えたかを残す。まちがえたときに前の設定へ戻せる |
| 予約一覧・受けない時間 | 今日・今週・すべての一覧とキャンセル。お店全体の「受けない時間」を登録し、予約が重なるときは件数を知らせる（予約は消さない） | ◎ | お店の人が予約を手で入れる（電話で受けた予約）を入れるかどうか |
| 複数店舗 | 見本の2店を切りかえて見られるだけ。まとめて管理する画面はない | × | 入れない。1つの申し込みで1店 |
| 止まったときの連絡 | していない（ブラウザの中だけで動くので、止まるのはそのブラウザだけ） | ○ | 止まったことにだれが気づくか、お店へどう知らせるか、止まっている間の予約をどう受けるか（「お電話ください」の表示など）、障害のときの連絡の流れ |

## 本番で検討すること（見本では作っていないもの）

- **新しいお店を作る画面**：本番では、お店ごとにこちらで設定してお渡しする。お店が自分で「型を選んで」新しく作る画面は、本番で検討する
- **担当ごとの臨時休み**：見本の「受けない時間」はお店全体だけ。担当1人だけが休む日（臨時の休み）を入れられるようにするか
- **「指名なし」の割り当ての決め方**：見本は担当の並び順。ほかに「その日の予約が少ない人から」「順番に回す」などの決め方を選べるようにするか
- **席をつなげる**：見本では席をつなげない（カウンター2名席×2）。2つの席をつなげて大人数に出すしくみが要るか
- **テイクアウト**：見本は店内飲食の消費税10%だけ。テイクアウト（8%）を扱うなら、メニューごとに税率を持つ
- **祝日**：見本は祝日も営業する前提。休む日は臨時休業で入れる
- **メニュー・席・担当を消したとき**：見本では、予約が入っていれば件数を知らせ、予約は残す。本番では、残った予約をお店にどう知らせるか

## たけさんと協力先で決めること

- 上の表の「軽量版（本番）に入れるか」の印（◎○△×）を、1つずつ決める
- 確認の連絡を何で送るか（メール・LINE・SMS）、前日のお知らせを入れるか
- お客さんの情報（名前・電話・メール）をどこに置き、だれが見られて、いつ消すか
- 二重予約をサーバー側で防ぐしくみと、データの保存場所をどうするか
- お店のログインの形（お店の人が何人で使うか、パスワードを忘れたとき）
- お店への設定の渡し方（こちらで設定してお渡しする流れ、お店が自分で変えてよい範囲）
- 止まったときに、だれが気づき、お店へどう知らせ、その間の予約をどう受けるか
- 最初に試してもらうお店（飲食店・サロン）と、試す期間
